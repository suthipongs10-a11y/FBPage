# แพ็กเกจลูกค้า + โควต้าโพสต์ต่อเดือน + ภาพรวมทุกเพจ

หน้า **ภาพรวมทุกเพจ** (`/portfolio`) มีสองแท็บ:
- **แท็บ "เพจ"** ดูทุกเพจที่ดูแลได้ในหน้าเดียว: แพ็กเกจ, โพสต์รอบนี้เทียบโควต้า, งานค้าง และเพจไหนต้องรีบดู
- **แท็บ "แพ็กเกจ"** จัดการแพ็กเกจบริการ (ราคา/โควต้า)

## แพ็กเกจ (`ServicePlan`)
- **ราคา:** เป็นบาทต่อเพจต่อเดือน (`priceMonthly`)
- **โควต้าโพสต์:** `postsPerMonth`, เว้นว่าง = ไม่จำกัด
- **Reels:** `reelsPerMonth` เป็นโควต้าย่อยที่**นับรวมอยู่ในโพสต์** (ตั้งเกินโควต้าโพสต์ไม่ได้)
- **บริการที่รวม:** `features` (`PLAN_FEATURES` ใน `@fbpm/shared`) มีไว้แสดงผลอย่างเดียว ไม่ได้เปิด/ปิดฟีเจอร์ในระบบ
- **ตัวอย่างสำเร็จรูป:** ปุ่มตัวอย่างมี 3 แบบ (590 / 990 / 1,990) กดแล้วแค่เติมฟอร์มให้ ผู้ใช้แก้ก่อนบันทึก
- **ลบแพ็กเกจ:** ลบได้เฉพาะแพ็กเกจที่ไม่มีเพจใช้ ถ้ามีเพจใช้อยู่ให้กด "ปิดรับ" แทน (เพจเดิมยังใช้ต่อได้ แต่กำหนดให้เพจใหม่ไม่ได้)
- **สิทธิ์:**
  - สร้าง/แก้/กำหนดแพ็กเกจต้องมี `client.manage`
  - ดูรายการแพ็กเกจต้องมี `client.read`
  - ราคาและรายได้แสดงเฉพาะคนที่มี `client.manage` (API ตัดฟิลด์ `priceMonthly` ออกสำหรับบทบาทอื่น)
- **ลูกค้าในพอร์ทัล:** เห็นชื่อแพ็กเกจและโควต้าของเพจตัวเอง ไม่เห็นราคา

## กำหนดให้เพจ
`PATCH /workspaces/:ws/pages/:pageId/plan {servicePlanId|null, billingDay 1–28}` → บันทึก `FacebookPage.servicePlanId / billingDay / planStartedAt` (มี audit)

## การนับโควต้า
`billingCycle()` และ `quotaStatus()` ใน `packages/shared/src/quota.ts` เป็นฟังก์ชันบริสุทธิ์ มี unit test

- **รอบ:** เริ่มวันตัดรอบเวลา 00:00 ตามเขตเวลาของเพจ (ถ้าไม่ตั้ง = เขตเวลาของ workspace) จนถึงก่อนวันเดียวกันของเดือนถัดไป
- **ใช้ไปแล้ว (used):** ContentItem Facebook ที่สถานะ `PUBLISHED` / `ANALYZED` และ `publishedAt` อยู่ในรอบ
- **ตั้งเวลาไว้ (scheduled):** สถานะ `SCHEDULED` / `PUBLISHING` และ `scheduledAt` อยู่ในรอบ
  - งานที่ตั้งเวลาไว้รอบหน้า ไม่นับในรอบนี้
- **ลงไว้แล้ว (planned):** used + scheduled
- **สถานะ (pace):**
  - `BEHIND` — planned น้อยกว่าที่ควรมีตามเวลาที่ผ่านไป (floor(โควต้า × สัดส่วนเวลา))
  - `FULL` — ครบพอดี
  - `OVER` — เกินโควต้า
  - `ON_TRACK` — ตามแผน
  - `UNLIMITED` — แพ็กเกจไม่จำกัด
  - `NO_PLAN` — ยังไม่มีแพ็กเกจ
- **โพสต์นอกระบบ:** `pagePosts` = โพสต์บนเพจในรอบนี้จาก `FacebookPost` ที่ซิงก์มา (รวมที่โพสต์นอกระบบ) แสดงเพื่อข้อมูลเท่านั้น ไม่นับเป็นโควต้า
- **โควต้าไม่บล็อกงาน:** ตั้งเวลาหรือโพสต์เกินโควต้าได้ ระบบแค่ขึ้นป้าย "เกินโควต้า" ให้ทีมตัดสินใจเอง

## ภาพรวม (`GET /workspaces/:ws/portfolio`, สิทธิ์ `page.read`)
แสดงทุกเพจที่ยังเชื่อมต่อ แต่ละแถวมี:
- ลูกค้า/แบรนด์, แพ็กเกจ, รอบ, โควต้า, Reels
- งานค้าง: รออนุมัติ, อนุมัติแล้วยังไม่ตั้งเวลา, โพสต์ล้มเหลว, คอมเมนต์รอตอบ, แชทรอคนตอบ, ลีดใหม่
- โพสต์ล่าสุด / โพสต์ถัดไป
- ป้ายต้องดู `attention`:
  - `TOKEN` — token เพจใช้ไม่ได้
  - `PAUSED` — หยุดโพสต์อยู่
  - `FAILED` — มีโพสต์ล้มเหลว
  - `BEHIND` — โพสต์ช้ากว่าแผน
  - `OVER` — เกินโควต้า
  - `REELS_OVER` — Reels เกินโควต้า
  - `NO_PLAN` — ยังไม่มีแพ็กเกจ
  - `NO_UPCOMING` — ยังเหลือโควต้าแต่ไม่มีโพสต์ตั้งเวลาใน 3 วัน
  - `STALE` — ไม่มีโพสต์ใหม่ 7 วัน
  - `APPROVAL` — มีงานรออนุมัติ

สรุปรวมด้านบนมีจำนวนเพจ, รายได้ต่อเดือน (ถ้ามีสิทธิ์), โพสต์รอบนี้/โควต้า, เพจช้ากว่าแผน/ต้องดู และแยกตามแพ็กเกจ

ในหน้ามีตัวกรอง (ต้องดู / ช้ากว่าแผน / เกินโควต้า / ยังไม่มีแพ็กเกจ / ลูกค้า / ค้นหา) และปุ่มดาวน์โหลด CSV (มี BOM ให้ Excel อ่านภาษาไทยถูก)

หน้าเพจ (`/pages/<id>`) มีการ์ดโควต้าจาก `GET /workspaces/:ws/pages/:id/quota`
