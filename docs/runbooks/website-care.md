# ดูแลเว็บไซต์ลูกค้า (Website Care W-1/W-2)

## เพิ่มเว็บ
หน้า **เว็บไซต์ → เพิ่มเว็บไซต์**: เลือกแบรนด์ → ใส่ URL → (แนะนำ) ใส่ "คำที่ต้องพบในหน้าแรก" เช่น ชื่อร้าน เพื่อจับกรณีเว็บขึ้นแต่เนื้อหาหาย → บันทึก ระบบตรวจ uptime/SSL/SEO ทันทีและตรวจซ้ำตามรอบ (ค่าเริ่มต้น 15 นาที) ส่วน SSL/SEO/ลิงก์/PageSpeed/Search Console ตรวจวันละครั้งตี 2 UTC
- เว็บล่ม: ต้องล้ม 2 รอบติดกันจึงแจ้งเตือน (กัน false alarm) และแจ้งอีกครั้งเมื่อฟื้น · SSL ≤ 14 วันแจ้งเตือน · ช้าเกิน 3 วิ = "ช้า/ไม่แน่ใจ"
- ระบบ **ไม่แก้เว็บลูกค้า** และตรวจแบบสุภาพ (UA `FBPM-SiteMonitor/1.0`, ≤ 1 คำขอ/วินาที, เคารพ robots.txt)

## Core Web Vitals
ต้องมี `PAGESPEED_API_KEY` (Google Cloud → PageSpeed Insights API → API key ฟรี) ไม่มี = แสดง "ไม่มีข้อมูล" ไม่ใช่ 0

## Search Console
1. หน้า YouTube → *เชื่อมบัญชี Google* (ระบบขอ scope Search Console ด้วยแล้ว) หรือให้เจ้าของเว็บกด
2. เจ้าของเว็บเพิ่มอีเมลบัญชี Google นั้นเป็น **user** ของ property ใน Search Console (Settings → Users and permissions)
3. หน้าเว็บไซต์ → เลือกเว็บ → *เชื่อม Search Console* → ระบบจับคู่ property ให้เอง (`sc-domain:` ก่อน แล้ว URL prefix) → ซิงก์ 28 วัน
- ข้อมูล Google ล่าช้า 2–3 วัน · ไม่มีสิทธิ์ = สถานะ "ไม่มีสิทธิ์" + แจ้งเตือน ไม่ใช่เลข 0

## SEO Analyst
ปุ่ม *ให้ AI วิเคราะห์ SEO* ใช้เฉพาะข้อมูลที่ระบบตรวจได้ (audit, PageSpeed, Search Console, ข้อมูลแบรนด์) แยก OBSERVED / INFERENCE / RECOMMENDATION พร้อม effort — ห้ามอ้างอันดับหรือคู่แข่งที่ไม่มีในข้อมูล

## ปัญหาที่พบบ่อย
| อาการ | ทำอย่างไร |
| --- | --- |
| "ไม่อนุญาตเป้าหมายในเครือข่ายภายใน" | URL เป็น IP ภายใน/localhost — ใช้โดเมนจริง (test ตั้ง `WEB_ALLOW_PRIVATE_TARGETS=true`) |
| SSL = "ไม่ใช่ https" | เว็บลูกค้ายังไม่มี HTTPS — แนะนำลูกค้าเปิด (Let's Encrypt ฟรี) |
| Search Console "ไม่มีสิทธิ์" | เจ้าของเว็บยังไม่เพิ่มบัญชี Google เป็น user ของ property หรือบัญชีเชื่อมโดยไม่มี scope ค้นหา → เชื่อมบัญชี Google ใหม่ |
| PageSpeed FAIL | หน้าแรกโหลดไม่สำเร็จจากฝั่ง Google หรือ key ผิด — ดูข้อความ error ในการ์ด |

## บทความขึ้นเว็บ (W-3)
1. **เชื่อม WordPress ต่อเว็บ** — ที่ WordPress: Users → Profile → Application Passwords → สร้างชื่อ "AI Page Manager" (บัญชีต้องเป็น Editor ขึ้นไป) แล้วคัดลอกรหัสที่ได้
2. หน้า **เว็บ · บทความ** → *เชื่อม WordPress* → เลือกเว็บ + ใส่ username และ Application Password → ระบบยิงตรวจจริงกับเว็บ (`/wp-json/wp/v2/users/me`) แล้วบอกชื่อผู้ใช้ที่เชื่อมได้ · รหัสเก็บแบบเข้ารหัสและไม่แสดงซ้ำ
3. *บทความใหม่* → ใส่หัวข้อ/คำค้นเป้าหมาย → เลือกคลิป YouTube หรือโพสต์ Facebook ของแบรนด์เดียวกันเป็นแหล่ง → *ให้ AI ร่าง*
4. ตรวจเนื้อหา: ถ้ามี `[ต้องยืนยัน: ...]` ต้องเติมข้อมูลจริงก่อน (ระบบไม่ให้ผ่านการตรวจ) → *ส่งขออนุมัติ* → *อนุมัติ* → *เผยแพร่ขึ้นเว็บ* (หรือส่งเป็นฉบับร่างบน WordPress / ตั้งเวลา)
5. แก้บทความที่เผยแพร่แล้ว: แก้ในระบบไม่ได้โดยตรง — ใช้ *อัปเดตบน WordPress* (คนกดเท่านั้น)
- ต้องตั้ง `WEB_PUBLISH_ENABLED=true` จึงจะยิงขึ้นเว็บจริง · หยุดฉุกเฉินได้ที่ `publishingPaused` ต่อเว็บ หรือสวิตช์ระดับ workspace
- ยิงซ้ำ/worker retry ไม่ทำให้เกิดโพสต์ซ้ำ (กันด้วย ExternalOperation + ค้นหา slug เดิมก่อนสร้าง)

## อีเมลการตลาด (W-4)
1. สมัคร **Brevo** หรือ **Resend** → ยืนยันโดเมนผู้ส่ง (SPF/DKIM) ให้ครบก่อนส่งจริง มิฉะนั้นอีเมลจะเข้าสแปม/ถูกปฏิเสธ
2. หน้า **อีเมล** → *ผู้ให้บริการส่งอีเมล* → เลือก brevo/resend + วาง API key (+ webhook secret ถ้าจะรับสถิติ) → ระบบตรวจ key ให้ทันที
3. ตั้ง webhook ที่ผู้ให้บริการให้ชี้มาที่ URL ที่หน้าเว็บบอก — Brevo ใส่ `?token=<secret>` ต่อท้าย, Resend ใช้ signing secret (`whsec_…`) · **ต้องตั้ง secret** ไม่งั้นระบบปฏิเสธ webhook ทั้งหมด (กันคนยิงสถิติปลอม) และสถิติเปิด/คลิกจะขึ้นว่า "ไม่มีข้อมูล" (ไม่ใช่ 0)
4. *สร้างรายชื่อ* (ผูกแบรนด์, อีเมล/ชื่อผู้ส่ง) → *นำเข้าผู้รับ* — ต้องติ๊กยืนยันว่าทุกคนยินยอมแล้วและระบุที่มาของความยินยอม (PDPA) · คนที่เคยยกเลิกรับจะไม่ถูกเปิดกลับด้วยการ import
5. *แคมเปญใหม่* → *ให้ AI ร่าง* (ใช้คอนเทนต์ที่เผยแพร่แล้วของแบรนด์) → ตรวจ → *ส่งขออนุมัติ* → *อนุมัติ* → *ส่งทดสอบถึงตัวเอง* → *ส่งตอนนี้* หรือ *ตั้งเวลาส่ง*
- ต้องตั้ง `EMAIL_SEND_ENABLED=true` จึงจะส่งจริง · หยุดฉุกเฉินได้ที่ *หยุดส่งทั้งหมด*
- ทุกฉบับมีลิงก์ยกเลิกรับ + header `List-Unsubscribe` · bounce/แจ้งสแปม → ระบบปิดผู้รับให้อัตโนมัติ
- อีเมลแจ้งเตือนภายใน (SMTP_*) แยกจากระบบนี้ — ห้ามใช้ SMTP ภายในส่งการตลาดจำนวนมาก
