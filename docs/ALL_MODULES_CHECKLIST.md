# คู่มือตั้งค่าและตรวจรับทุกโมดูล

> สถานะต่อเนื่อง 14 กันยายน 2026: อ่าน [SOCIALMANAGE_HANDOFF.md](SOCIALMANAGE_HANDOFF.md) ประกอบ งานจริงให้ Facebook มาก่อน Messenger ใช้ร่างรอตรวจเป็นค่าเริ่มต้น ยังไม่ deploy หรือเชื่อม MCP; อย่าทำขั้นทดสอบเผยแพร่/ส่งข้อความ/เรียก AI เสียเงินจริงโดยไม่มีการอนุญาตเฉพาะ

อัปเดต 11 กันยายน 2026 — สำหรับโปรเจ็กต์ `C:\Work\SocialManage\fbpage`

คู่มือนี้รวมค่าที่แอปต้องใช้และรายการทดสอบตามโมดูลที่มีอยู่จริง ส่วน [LOCAL_SETUP](LOCAL_SETUP.md) ใช้เปิดเครื่องและตั้งค่า TikTok/Gemini โดยละเอียด ไม่ใช่คู่มือครบทุกโมดูล

## สถานะที่ยืนยันได้

- ผลทดสอบล่าสุดวันที่ 11 กันยายน: unit/integration **249 เคสผ่าน**; browser **11 เคสผ่าน** รวม Messenger ใหม่ ดูรายละเอียดใน [TEST_REPORT](TEST_REPORT.md)
- การทดสอบดังกล่าวใช้บริการภายนอกจำลอง ไม่ได้ยืนยันการเชื่อมบัญชีจริง การส่งอีเมลจริง หรือการเผยแพร่จริง
- การเปิดหน้าเว็บได้หรือทดสอบคีย์ผ่าน ยังไม่เท่ากับโมดูลทำงานครบ ต้องตรวจตั้งแต่บันทึก → ประมวลผล → ผลลัพธ์ปลายทาง
- รายการด้านล่างยังไม่ถูกทำเครื่องหมายผ่าน จนกว่าจะมีผลทดสอบจริงของบัญชีที่จะใช้งาน

## 1. ตั้งค่าที่ไหน

ค่าที่ระบุ `.env` ให้แก้ไฟล์ที่ root ของโปรเจ็กต์ ส่วนค่าที่ระบุหน้าเว็บให้กรอกใน workspace ที่ต้องการใช้งาน ไม่ต้องส่งคีย์ลงแชต

| โมดูล | ค่าที่ต้องเตรียม | กรอกที่ไหน |
|---|---|---|
| ระบบหลัก / ลูกค้า / แบรนด์ | ฐานข้อมูล, Redis, `AUTH_SECRET`, `APP_URL` — เครื่องนี้เตรียมไว้แล้ว | `.env`; สมัครและสร้างลูกค้า/แบรนด์บนเว็บ |
| AI ทุกโมดูล / AI Command | คีย์ผู้ให้บริการอย่างน้อยหนึ่งราย เช่น Gemini และโมเดลที่บัญชีใช้ได้ | หน้า **โมเดล AI** แล้วเลือกโมเดลตามบทบาท; หรือ `GOOGLE_AI_API_KEY` ใน `.env` เป็นค่าระดับระบบ |
| Facebook | Page access token สำหรับวิธีวางโทเค็น; ถ้าใช้ OAuth เพิ่ม `META_APP_ID`, `META_APP_SECRET`, `META_OAUTH_REDIRECT_URI` | โทเค็นในหน้า **เพจ**; ค่าแอปใน `.env` |
| Facebook webhook | `META_WEBHOOK_VERIFY_TOKEN` และปลายทาง webhook ที่เข้าถึงได้จากภายนอก | `.env` และการตั้งค่าแอป Meta; ไม่จำเป็นสำหรับเริ่มทดสอบซิงก์ด้วยมือ |
| Messenger / แชทอัตโนมัติ | คีย์ OpenAI แยกสำหรับแชท, โมเดล, Meta App/webhook และ `pages_messaging` | หน้า **แชทอัตโนมัติ** → ทดลอง AI → เชื่อมรับข้อความ → เปิดเฉพาะเพจเป้าหมาย; [คู่มือ Messenger](MESSENGER.md) |
| YouTube | `YOUTUBE_API_KEY`; การเชื่อมช่องส่วนตัว/Analytics/สิทธิ์อัปโหลดใช้ `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_OAUTH_REDIRECT_URI` | `.env` แล้วเชื่อมช่องในหน้า **YouTube** |
| TikTok | `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `TIKTOK_REDIRECT_URI` และสิทธิ์แอป | `.env` แล้วเชื่อมบัญชีในหน้า **TikTok**; ดูรายละเอียด callback ใน LOCAL_SETUP |
| เว็บไซต์: uptime / SSL / SEO / ลิงก์ | URL เว็บไซต์สาธารณะ | หน้า **เว็บไซต์**; เริ่มตรวจพื้นฐานได้โดยไม่มี API key |
| PageSpeed | `PAGESPEED_API_KEY` เป็นค่าเสริมของการตรวจความเร็ว | `.env` |
| Search Console | Google OAuth ชุดเดียวกับด้านบน และบัญชีที่มีสิทธิ์ใน property เป้าหมาย | เชื่อม Google และเลือก property ในโมดูลเว็บไซต์ |
| WordPress | URL เว็บ, username และ Application Password ของผู้ใช้ที่มีสิทธิ์เขียน | หน้า **เว็บ · บทความ** / การเชื่อม WordPress |
| Email marketing | คีย์ Brevo หรือ Resend, ผู้ส่ง/โดเมนที่พร้อมส่ง และการตั้งค่า webhook ตามผู้ให้บริการ | หน้า **Email** ตั้งค่าผู้ให้บริการและผู้ส่ง |
| อีเมลระบบ / คำเชิญ / รีเซ็ตรหัสผ่าน | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `SMTP_SECURE` ตามบริการที่ใช้ | `.env`; ทดสอบใน **ตั้งค่า** |
| การแจ้งเตือนภายนอก | URL webhook ของช่องทางที่ต้องการรับแจ้งเตือน | หน้า **ตั้งค่า**; ไม่จำเป็นต่อการเปิดระบบหลัก |
| Media / PDF / รายงาน | `MEDIA_DIR`; Chrome/Edge สำหรับเรนเดอร์; `CHROME_BIN` เมื่อค้นหาโปรแกรมไม่พบ | เครื่องนี้เตรียม runtime ไว้แล้ว; สรุปด้วย AI ต้องมีคีย์ AI เพิ่ม |

คีย์ AI ไม่ใช้แทนคีย์ Google OAuth/YouTube และคีย์ Email marketing ไม่ใช้แทนรหัส SMTP โดยอัตโนมัติ

หลังแก้ `.env` ให้รีสตาร์ททั้ง API เว็บ และ worker ด้วยคำสั่งนี้จากโฟลเดอร์โปรเจ็กต์:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/local.ps1 stop
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/local.ps1 start
```

ไม่ต้องสร้างฐานข้อมูลใหม่ และอย่าเปลี่ยน `AUTH_SECRET` ที่ใช้เข้ารหัสโทเค็นเดิม การบันทึกคีย์ผ่านหน้าเว็บไม่ต้องแก้ `.env`

สำหรับ OAuth ให้ URL callback ที่ลงทะเบียนตรงกับค่าของแอปทุกตัวอักษร และใช้แนวทาง same-origin ใน LOCAL_SETUP สำหรับ TikTok ส่วน webhook จากบริการภายนอกต้องมี URL ที่บริการนั้นเรียกถึงได้; `localhost` บนเครื่องนี้ไม่ใช่ปลายทางสาธารณะ

## 2. รายการตรวจรับทีละโมดูล

ใช้ลูกค้า/แบรนด์สำหรับทดสอบ และบันทึกผลจริงในตารางท้ายเอกสาร เริ่มจากการอ่านข้อมูลและเตรียมร่าง แล้วจึงทดสอบการส่งในบัญชีทดสอบที่เลือกไว้

- [ ] **บัญชี / workspace / สมาชิก:** สมัคร → เข้าสู่ระบบ → ออกจากระบบ → เข้าใหม่; เพิ่มสมาชิกและตรวจว่าบทบาทจำกัดการแก้ไข/อนุมัติได้ตามสิทธิ์ และไม่เห็นข้อมูล workspace อื่น
- [ ] **ลูกค้า / แบรนด์ / ความรู้แบรนด์:** สร้างและแก้ไขข้อมูล → รีเฟรชแล้วยังอยู่ → เลือกแบรนด์ถูกต้องในโมดูลคอนเทนต์
- [ ] **โมเดล AI:** บันทึกคีย์ → ทดสอบ → ตั้งโมเดลตามบทบาท → สร้างร่างสั้นหนึ่งชิ้น → ตรวจข้อความและประวัติงาน/การใช้งาน; คีย์ผ่านแต่รุ่นโมเดลไม่มีสิทธิ์ยังไม่นับว่าผ่าน
- [ ] **AI Command:** สั่งงานกับลูกค้า/แบรนด์ทดสอบ → ตรวจผลลัพธ์อ้างอิงแบรนด์ถูกต้องและดูประวัติงานได้
- [ ] **Facebook / เพจ:** เชื่อมเพจ → ซิงก์ → ตรวจชื่อเพจและโพสต์ตัวอย่างเทียบกับเพจจริง; ซิงก์ซ้ำแล้วไม่เกิดรายการซ้ำ
- [ ] **Messenger:** กรอกคีย์แชทแยก → ทดลองถามจากข้อมูลแบรนด์ → เชื่อมรับข้อความเพจทดสอบ → เปิดตอบอัตโนมัติ → ลูกค้าทดสอบทักแล้วได้รับคำตอบโดยไม่ต้องอนุมัติ; ตรวจว่าเพจที่ปิดไม่ตอบ → แอดมินรับช่วงแล้วบอตหยุด → เปิดต่อแล้วตอบเฉพาะข้อความใหม่
- [ ] **Content / อนุมัติ:** สร้างร่าง → แก้ไข → ส่งตรวจ → อนุมัติด้วยผู้มีสิทธิ์ → ตรวจสถานะและประวัติ; ทดสอบการปฏิเสธด้วย
- [ ] **Calendar / คิวงาน:** ตั้งงานในอนาคต → เวลาแสดงถูกต้องตาม Asia/Bangkok → worker รับงาน → สถานะสำเร็จหรือเหตุขัดข้องแสดงชัด; ใช้ชิ้นงานทดสอบเมื่อถึงขั้นส่งจริง
- [ ] **Facebook Analytics / Overview:** เลือกช่วงเวลา → ซิงก์ → ตรวจยอดกับข้อมูลที่ API ให้ในช่วงเดียวกัน; แยกค่าที่ไม่มีข้อมูลออกจากศูนย์
- [ ] **Facebook Comments:** ดึงคอมเมนต์ของโพสต์ทดสอบ → จัดหมวด/สร้างคำตอบด้วย AI → ตรวจร่าง; การตอบหรือซ่อนจริงให้ทำเฉพาะคอมเมนต์ทดสอบ
- [ ] **Leads:** ตรวจรายการจากคอมเมนต์ที่เข้าเงื่อนไข → เปลี่ยนสถานะและเพิ่มบันทึก → รีเฟรชแล้วข้อมูลคงอยู่
- [ ] **TikTok แบบไม่มีคีย์:** เลือกแบรนด์โดยยังไม่เลือกบัญชี → เขียนร่าง → ตรวจ/อนุมัติ → ดาวน์โหลด TXT ภาษาไทย; ปุ่มส่งต้องยังไม่พร้อมจนกว่าจะตั้งค่าครบ
- [ ] **TikTok บัญชีจริง:** OAuth → ตรวจโปรไฟล์ → ซิงก์วิดีโอ → ตรวจยอดและวันที่; ลอง Studio เมื่อมีคีย์ AI; เมื่อผูกร่างเข้าบัญชีภายหลังต้องตรวจ/อนุมัติใหม่
- [ ] **YouTube / Videos:** เชื่อมช่อง → ซิงก์วิดีโอ → ตรวจชื่อช่อง/วิดีโอและสถิติ; ข้อมูล Analytics ต้องตรวจด้วยบัญชีที่มีสิทธิ์ช่องนั้น
- [ ] **YouTube Content / Comments / Reports:** เตรียมร่าง → ตรวจอนุมัติ; ดึงคอมเมนต์ → เตรียมคำตอบ; สร้างรายงานตามช่วงเวลาและตรวจตัวเลขต้นทาง
- [ ] **Website Care:** เพิ่ม URL → ตรวจ uptime, SSL, SEO, ลิงก์ → ดูรายละเอียดข้อผิดพลาดและประวัติ; PageSpeed/เครือข่ายล้มเหลวต้องแสดงเหตุผล ไม่ถือว่าทุกการตรวจผ่าน
- [ ] **Search Console:** เชื่อมบัญชี → เลือก property ที่มีสิทธิ์ → ดึงข้อมูลช่วงวันที่มีข้อมูลจริง → ตรวจคำค้น/ยอด; property ว่างยังไม่ยืนยันการดึงข้อมูลครบ
- [ ] **WordPress:** เชื่อมเว็บทดสอบ → เตรียมบทความ → ตรวจ/อนุมัติ → เมื่อเปิดส่งจริงให้ตรวจบทความและสถานะที่ WordPress ด้วย
- [ ] **Email marketing:** เชื่อมผู้ให้บริการ → เตรียมผู้รับทดสอบที่ยินยอม → สร้างและตรวจแคมเปญ → ส่งทดสอบ → ตรวจกล่องจดหมายและสถานะ; ตรวจ unsubscribe แล้วผู้รับนั้นต้องถูกกันจากการส่งครั้งถัดไป
- [ ] **Media:** เพิ่มไฟล์ทดสอบ → เปิดดู/นำไปใช้ในร่าง → ตรวจภาพที่สร้างหรือเรนเดอร์ได้จริง
- [ ] **Reports / PDF / แชร์:** สร้างรายงาน → เทียบช่วงเวลาและข้อมูล → เปิด PDF ตรวจภาษาไทย/หน้ากระดาษ → ทดลองลิงก์แชร์และการเพิกถอนสิทธิ์ที่มีในหน้าเว็บ
- [ ] **Settings / Notifications / SMTP:** บันทึกค่า → รีเฟรช; ส่งอีเมลทดสอบถึงตนเองและตรวจการรับจริง; ทดสอบคำเชิญ/รีเซ็ตด้วยบัญชีทดสอบ; ตรวจช่องทางแจ้งเตือนที่เลือกใช้งาน

## 3. เปิดการส่งจริงแยกตามโมดูล

| โมดูล | เงื่อนไขเพิ่มก่อนส่ง | ผลที่ต้องตรวจ |
|---|---|---|
| Facebook | สิทธิ์เพจ, การอนุมัติ และสถานะ pause ของ workspace/เพจ | โพสต์ทดสอบปรากฏบนเพจที่เลือก |
| YouTube | `YOUTUBE_UPLOAD_ENABLED=true` และสิทธิ์ช่อง/การอนุมัติ | ตรวจวิดีโอและสถานะในช่องทดสอบ |
| WordPress | `WEB_PUBLISH_ENABLED=true` และการเชื่อมเว็บ/อนุมัติ | บทความอยู่บนเว็บทดสอบตามสถานะที่สั่ง |
| Email | `EMAIL_SEND_ENABLED=true`, ผู้ส่งพร้อม, ผู้รับยินยอม และการอนุมัติตามขั้นตอน | ผู้รับทดสอบได้รับจริงและสถานะติดตามถูกต้อง |
| TikTok | `SOCIAL_PUBLISHING_ENABLED=true`, `TIKTOK_VERIFIED_MEDIA_PREFIXES`, URL MP4 HTTPS ที่ผ่านเงื่อนไข, สิทธิ์บัญชี และการยืนยัน/อนุมัติ | วิดีโอเข้า TikTok Inbox; เจ้าของบัญชีต้องโพสต์ต่อเอง |

`SOCIAL_PUBLISHING_ENABLED` ในรุ่นนี้ใช้กับ TikTok ไม่ใช่สวิตช์หยุด Facebook ทุกเพจ ส่วน TikTok ยังไม่รองรับ Direct Post หรืออัปโหลดไฟล์จากเครื่องโดยตรง การเข้า Inbox จึงห้ามนับเป็นโพสต์สาธารณะสำเร็จ

เมนู **Automation · เร็วๆ นี้** ยังไม่มีหน้าสร้าง automation ให้ตรวจรับ แม้ระบบมี worker และงานเบื้องหลังบางส่วนแล้ว จึงไม่ควรรายงานว่าทุกฟีเจอร์ในแผนโครงการเสร็จหมด

## 4. บันทึกผลจริง

เลือกสถานะ: **ผ่าน / ไม่ผ่าน / รอคีย์หรือสิทธิ์ / ยังไม่ทดสอบ / ยังไม่รองรับ** อย่าใช้ “ผ่าน” แทนกรณีเปิดหน้าได้แต่ยังไม่ได้ตรวจผลปลายทาง

| วันเวลา | โมดูล / ขั้นตอน | บัญชีหรือแบรนด์ทดสอบ (ไม่ใส่คีย์) | สถานะ | หลักฐาน / ข้อผิดพลาด |
|---|---|---|---|---|
| — | — | — | ยังไม่ทดสอบ | — |

ลำดับเริ่มใช้งาน: ระบบหลัก/แบรนด์ → AI → Facebook → YouTube → เว็บไซต์/Search Console → WordPress → Email → TikTok → รายงานและแจ้งเตือน โดยแต่ละโมดูลเริ่มตรวจได้ทันทีที่มีข้อมูลของโมดูลนั้น ไม่ต้องรอคีย์ครบทั้งหมด
