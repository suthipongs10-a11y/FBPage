# เชื่อมช่อง YouTube ของลูกค้ารายแรก (YT-1 → YT-7)

**ก่อนเริ่ม**: ตั้งค่า Google Cloud ตาม `google-cloud-setup.md` · ลูกค้า/แบรนด์สร้างไว้แล้ว (หน้า "ลูกค้า") · โมเดล AI ตั้งบทบาท `strategy/content/analysis/community/fast` แล้ว (หน้า "โมเดล AI")

## 1. เชื่อมต่อ (หน้า YouTube)
- **ทางหลัก**: กด *เชื่อมบัญชี Google* → เจ้าของช่องล็อกอินและยินยอม → กลับมาที่ระบบ → เลือกแบรนด์ → *เชื่อมช่อง* (โหมด OAuth)
- **อ่านสาธารณะ**: ถ้าลูกค้ายังไม่ให้สิทธิ์ ใส่ `@handle` ในโหมด API key → ได้วิดีโอ/วิว/ไลก์สาธารณะ (ไม่มี watch time/AVD/sub+/คอมเมนต์ตอบ/อัปโหลด) — รายงานจะบอกข้อจำกัดเอง
- ระบบทำ progressive sync ทันที: ข้อมูลช่อง (1 unit) → วิดีโอ 30 รายการล่าสุด (ผ่าน uploads playlist) → กด *ซิงก์ทั้งหมด* เพื่อดึง Analytics 28 วัน + คอมเมนต์ + playlists; *ดึงประวัติทั้งช่อง* เมื่อต้องการย้อนหลังทั้งหมด (คิดโควตา ~1 unit/50 วิดีโอ)
- worker ซิงก์ให้เองทุก 6 ชม. (quick) และรายวัน (videos + analytics) — ต้องรัน `pnpm dev:worker` ด้วย `AUTH_SECRET` เดียวกับ API

## 2. วิเคราะห์ (YT-3)
- *วิเคราะห์ช่อง* → Analyst แยก OBSERVED / INFERENCE / RECOMMENDATION จาก snapshot ที่มี (ไม่ยิง API เพิ่ม) → ข้อเสนอเข้าคิว "ข้อเสนอจากนักวิเคราะห์" ให้กด รับ/ข้าม/ทำแล้ว
- *หาวิดีโอที่ควรฟื้น* → revival score จาก AVD/sub-conversion/อายุ (ต้องมีวิดีโอยาว ≥ 5)
- หน้า **YT · วิดีโอ**: ตาราง + รายละเอียด (baseline ต่อรูปแบบ, packaging diagnosis เป็น *สมมติฐาน* เพราะ API ไม่ให้ CTR) — แก้ชื่อ/description ได้ทีละวิดีโอผ่าน API (มี audit) ห้าม bulk

## 3. Content Lab (YT-4/YT-5)
1. *หาหัวข้อ* (Topic Opportunity) → ได้ IDEA หลายรายการ + ข้อค้นพบข้ามแพลตฟอร์ม
2. เลือกงาน → *เขียนสคริปต์* → *เสนอชื่อ* → *บรีฟภาพปก* → *metadata/SEO*
3. **คนกรอกฟิลด์นโยบาย**: สำหรับเด็ก / สื่อสังเคราะห์ / โปรโมทแบบชำระเงิน (AI ไม่ตัดสิน) + การมองเห็น + เวลาเผยแพร่
4. แนบไฟล์วิดีโอ (+ ภาพปก) → *ส่งตรวจ + ขออนุมัติ* (Reviewer เช็คข้ออ้าง/ราคา/นโยบาย; ถ้า AI ล่มจะข้ามและบอกไว้) → ผู้มีสิทธิ์ `youtube.content.approve` กด *อนุมัติ*
5. *เข้าคิวอัปโหลด* (worker ทำ resumable + ตรวจ processing ทุก 5 นาที) หรือ *อัปโหลดขึ้น YouTube* ทันที — idempotent ต่อ ContentItem ไม่มีทางอัปซ้ำ; kill switch ที่ระดับ workspace/ช่องหยุดได้ทุกเมื่อ
6. *แปลงเป็นโพสต์ Facebook* → ร่าง FACEBOOK 3 แบบเข้าคิวอนุมัติเพจ (ContentRelation `REPURPOSED_FROM`)

## 4. คอมเมนต์ (YT-6)
ซิงก์ → *ให้ AI จำแนก + ร่างตอบ* (ลีดร้อน → แจ้งเตือน + หน้า "ลีด") → คนกด *ส่ง* (ต้อง OAuth) → *จับกลุ่มหัวข้อ* → *สร้างไอเดียวิดีโอ* จากกลุ่มที่ถามซ้ำ

## 5. รายงาน (YT-7)
หน้า **YT · รายงาน** → เลือกช่อง/เดือน → สร้าง → คัดลอกข้อความส่งลูกค้าได้ทันที; ตัวเลขที่ไม่มีสิทธิ์อ่านขึ้น "ไม่มีข้อมูล" เสมอ

## เมื่อเจอปัญหา
| อาการ | สาเหตุ / วิธีแก้ |
| --- | --- |
| แจ้งเตือน "ต้องเชื่อมต่อ Google ใหม่" | refresh token ถูกเพิกถอน/หมดอายุ (`invalid_grant`) → เจ้าของช่องกด *เชื่อมบัญชี Google* ใหม่ |
| 429 "โควตา YouTube API หมดวันนี้" | รอรีเซ็ตเที่ยงคืน Pacific; ลดความถี่ซิงก์ หรือขอเพิ่มโควตา |
| อัปโหลดขึ้น "การอัปโหลดยังไม่เปิดใช้" | `YOUTUBE_UPLOAD_ENABLED=false` → ใช้แพ็กเกจที่ระบบเตรียมไว้อัปเองใน Studio |
| commentsStatus = NO_ACCESS | ไม่มี scope `youtube.force-ssl` หรือช่องปิดคอมเมนต์ทั้งหมด |
| Analytics ว่าง | ช่องเชื่อมแบบ API key หรือไม่มี scope `yt-analytics.readonly`; ข้อมูลใหม่ล่าช้า 24–72 ชม. |
