# แจ้งเตือน LINE + พอร์ทัลลูกค้า

ให้เจ้าของธุรกิจ (ลูกค้าที่จ้างดูแลเพจ) **ล็อกอินดู/ตอบคอมเมนต์และแชท ดูลีด อนุมัติโพสต์ เปิดรายงาน** ของร้านตัวเองได้
และ**รับแจ้งเตือนเข้า LINE** — ทีมงานก็ได้รับแจ้งเตือนทาง LINE แบบรวมทุกลูกค้า

## ภาพรวม

| ผู้ใช้ | เข้าที่ | เห็นอะไร |
|---|---|---|
| ทีมงาน (สมาชิก workspace) | แอปปกติ `/` | ทุกลูกค้าตามบทบาท (RBAC เดิม) |
| เจ้าของธุรกิจ | `/portal/<clientId>` | เฉพาะลูกค้าที่ได้รับเชิญ — คอมเมนต์/แชท/ลีด/โพสต์รออนุมัติ/รายงานของเพจในลูกค้านั้น |

- เจ้าของธุรกิจ**ไม่ใช่สมาชิก workspace** (ตาราง `ClientPortalMember` แยก) → API ของทีม (`/workspaces/...`) ตอบ 404 ทั้งหมด
- ทุก endpoint `portal/clients/:clientId/*` ตรวจสมาชิกภาพก่อน → ได้ `workspaceId` จากลูกค้า → กรองข้อมูลด้วย `clientId` เสมอ แล้วเรียก service เดิมของทีม (กฎ 24 ชม. ของ Messenger, สวิตช์หยุดฉุกเฉิน, audit ทำงานเหมือนเดิม — audit บันทึก userId ของเจ้าของ)
- ทีมงานเปิด `/portal/<clientId>` ได้ = "ดูแบบลูกค้า" (อ่านอย่างเดียว)
- สิทธิ์ต่อคน: `canReply` (ตอบคอมเมนต์/แชท อัปเดตลีด) · `canApprove` (อนุมัติ/ขอแก้โพสต์ Facebook) — ปรับได้ในการ์ด "พอร์ทัลลูกค้า"
- ไม่ส่ง token / psid / ข้อมูลภายในออกหน้าเว็บของเจ้าของ

## เชิญเจ้าของธุรกิจ

1. หน้า **ลูกค้า → (เลือกลูกค้า) → การ์ด "พอร์ทัลลูกค้า"** (สิทธิ์ `client.manage`)
2. ใส่อีเมลเจ้าของ (หรือเว้นว่าง = ใครมีลิงก์ก็ได้) เลือกสิทธิ์ → **สร้างลิงก์เชิญ**
3. คัดลอกลิงก์ `/portal/join/<token>` ส่งทาง LINE — ใช้ได้ 7 วัน ครั้งเดียว (DB เก็บ sha256 ของ token)
4. เจ้าของเปิดลิงก์ → ตั้งชื่อ + รหัสผ่าน (หรือใช้บัญชีเดิม) → เข้าพอร์ทัลทันที
5. ถอดสิทธิ์ = ลบสมาชิก + หยุด LINE ของคนนั้นสำหรับร้านนี้ (บัญชีผู้ใช้ยังอยู่)

เจ้าของที่ล็อกอินหน้า `/login` จะถูกพาไป `/portal` อัตโนมัติ (ไม่มี workspace)

## พอร์ทัล (มือถือเป็นหลัก)

- **💬 ข้อความ** — คอมเมนต์รอตอบ (มีร่าง AI ให้แก้ก่อนส่ง, กด "ไม่ต้องตอบ" ได้) + แชท Messenger (ส่งได้ภายใน 24 ชม. หลังลูกค้าทักล่าสุด, ส่งร่าง AI ได้, ผลไม่แน่นอนห้ามส่งซ้ำ — กฎเดียวกับหน้าทีม)
- **🔥 ลีด** — ลีดของเพจในร้าน, ปุ่มโทร, เปลี่ยนสถานะ/บันทึก (ทีมเห็นด้วย)
- **✅ อนุมัติโพสต์** — โพสต์ Facebook สถานะ `READY_FOR_APPROVAL` พร้อมรูป/คลิป (ไฟล์ผ่าน `portal/clients/:id/media/:assetId` ตรวจว่าเป็นของโพสต์ในร้าน) · อนุมัติ → `APPROVED` (ทีมตั้งเวลาต่อ) · ขอแก้ต้องใส่ความเห็น → `NEEDS_REVISION` · ทีมได้แจ้งเตือน `client_decision`
- **📊 รายงาน** — เปิดผ่านลิงก์แชร์ `/share/r/...` อายุ 7 วัน (payload เดิมที่ไม่มีข้อมูลภายใน)
- **🔔 LINE** — ขอรหัสผูก LINE และเลือกชนิดแจ้งเตือน

ขอบเขตตอนนี้: Facebook (คอมเมนต์/Messenger/ลีด/โพสต์/รายงาน) — YouTube/TikTok/เว็บยังไม่อยู่ในพอร์ทัล

## แจ้งเตือน LINE (LINE Official Account + Messaging API)

LINE Notify ปิดบริการแล้ว — ใช้ LINE OA ของทีม (ฟรี มีโควต้าข้อความต่อเดือน) ส่งแบบ push

### ตั้งค่าครั้งเดียว (ผู้ดูแล workspace)
1. สร้าง LINE Official Account → LINE OA Manager → ตั้งค่า → Messaging API → เปิดใช้งาน
2. LINE Developers console → channel นั้น: คัดลอก **Channel secret** (Basic settings) และกด Issue **Channel access token (long-lived)** (Messaging API)
3. หน้า **ตั้งค่า → แจ้งเตือนทาง LINE** วางทั้งสองค่า → บันทึก (ระบบเรียก `GET /v2/bot/info` ตรวจ token ก่อน เก็บเข้ารหัสด้วย `common/crypto`, ไม่คืนค่า/ไม่ลง audit)
4. คัดลอก **Webhook URL** (`https://<โดเมน>/api/line/webhook/<key สุ่ม>`) ใส่ในแท็บ Messaging API → เปิด **Use webhook** → กด Verify ต้องได้ Success
5. ปิด **Auto-reply messages** ของ OA (ไม่งั้น OA ตอบข้อความอัตโนมัติทับ)

### ผูก LINE ของแต่ละคน
- ทีมงาน: ตั้งค่า → "ผูก LINE ของฉัน" · เจ้าของ: พอร์ทัล → แท็บ LINE → "ขอรหัสผูก LINE"
- เพิ่มเพื่อน OA แล้วส่ง**รหัส 6 หลัก** (อายุ 30 นาที ใช้ครั้งเดียว) ในแชท → OA ตอบ "เชื่อมแจ้งเตือนแล้ว"
- webhook ตรวจลายเซ็น `x-line-signature` (HMAC-SHA256 ด้วย channel secret) ก่อนทำอะไร · unfollow/บล็อก OA → ปิดผู้รับ · push ได้ 400/403 → ปิดผู้รับเอง

### ใครได้อะไร
| ชนิด | ทีม (ค่าเริ่มต้น) | เจ้าของธุรกิจ (ค่าเริ่มต้น / เลือกได้) |
|---|---|---|
| `hot_lead` ลีดร้อน | ✅ | ✅ |
| `inbox_digest` สรุปคอมเมนต์/แชทใหม่ | ✅ (ข้อความเดียวรวมทุกลูกค้า) | ✅ (เฉพาะร้าน + ลิงก์พอร์ทัล) |
| `approval_required` โพสต์รออนุมัติ | ✅ | ✅ |
| `report_ready` | ✅ | ✅ |
| `publish_failed` | ✅ | เลือกเปิดได้ |
| `client_decision` ลูกค้าอนุมัติ/ขอแก้ | ✅ | — |
| `reconnect_required`, `ai_budget`, `comments_permission` | ✅ | — (เรื่องภายในทีม) |

- ต้นทางคือ `notify()` เดิม (`@fbpm/database/notify`) — หา `clientId` จาก resource เอง (เพจ/คอมเมนต์/ลีด/แชท/คอนเทนต์/ช่อง YouTube) แล้วส่งเฉพาะแจ้งเตือนใหม่ (dedupe ซ้ำไม่ส่ง LINE ซ้ำ)
- ข้อความทีมขึ้นต้นด้วย `[ชื่อลูกค้า]` + ลิงก์หน้าทีม · ข้อความเจ้าของมีลิงก์ `/portal/<id>?tab=...`
- **สรุปคอมเมนต์/แชท** (worker `line-inbox-digest-30m`): นับคอมเมนต์ใหม่ (ไม่นับของเพจเอง) + ข้อความแชทขาเข้าใหม่ + แชทรอคนตอบ ตั้งแต่ `Client.inboxDigestAt` (ย้อนไม่เกิน 24 ชม.) · ไม่มีอะไรใหม่ = ไม่ส่ง · **ช่วงเงียบ 22:00–07:00** ตามเขตเวลาของ workspace ไม่ส่งและไม่ขยับเวลาอ้างอิง → เช้ามาได้สรุปทั้งคืนในข้อความเดียว
- เพดาน `LINE_MAX_PUSH_PER_DAY` (ค่าเริ่มต้น 30) ต่อผู้รับต่อวัน — เกินแล้วบันทึก `SKIPPED daily_cap` · ทุกการส่งบันทึกใน `LineDelivery` (worker ลบเก่ากว่า 90 วัน)

## Deploy (VPS)
```
cd /opt/fbpm && git pull
docker compose build api && docker compose build worker && docker compose build web
docker compose --profile maintenance build migrate && docker compose --profile maintenance run --rm migrate   # migration 20260930120000_client_portal_line
docker compose --profile automation up -d
```
ไม่ต้องแก้ nginx (webhook อยู่ใต้ `/api/` เดิม) · เครื่องต้องออกเน็ตไป `api.line.me` ได้
