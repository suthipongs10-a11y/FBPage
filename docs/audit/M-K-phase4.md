## เรื่องที่ต้องตัดสินใจ แล้วตัดสินใจแบบไหน

### 1. ภาษาไทยไม่เว้นวรรค → ทุกอย่างเป็น substring

ใช้ `\b` ของ regex ไม่ได้เลย คำสั้นๆ จึงไปโดนคำอื่นเต็มไปหมด:

| คำสำคัญ | ไปโดน |
|---|---|
| `ขอ` | **ขอบคุณ** **ขอโทษ** ← คอมเมนต์ที่พบบ่อยที่สุดในเพจไทย |
| `ถูก` (ราคาถูก) | ถูกใจ · ถูกต้อง · ถูกหลอก |
| `ช้า` | ช้าง |
| `เสีย` | เสียง · เสียใจ · เสียดาย |
| `ไหม` (คำถาม) | ผ้าไหม · ไหมขัดฟัน |

ใช้สองชั้นกัน:

1. **ไม่ใส่คำที่กำกวมตั้งแต่แรก** — เลือก `อร่อย` แทน `ดี` (เพราะ "ดี" อยู่ใน
   "เดี๋ยว" "ดีไซน์" "ดีเลย์"), เลือก `สั่ง` แทน `เอา` (เพราะ "เอา" อยู่ในแทบทุกประโยค)
2. **ตัดวลียกเว้นทิ้งก่อนแมตช์** — วิธีเดียวกับที่ `packages/moderation` พิสูจน์มาแล้ว

### 2. เลือกความแม่นมากกว่าความครบ

ตัวเลขพวกนี้คนเอาไปตัดสินใจจริง ("คนบ่นเรื่องราคา 12 คอมเมนต์ → ลดราคาดีไหม")
นับเกินเพราะไปจับ "ขอบคุณ" เป็น "อยากสั่งของ" **อันตรายกว่านับขาด**

หน้าจอจึงบอกตรงๆ ว่ามีกี่คอมเมนต์ที่ไม่เข้าหัวข้อไหนเลย แทนที่จะปล่อยให้คนคิดว่า
ตัวเลขที่เห็นครอบคลุมทั้งหมด

### 3. หนึ่งคอมเมนต์อยู่ได้หลายหัวข้อ และคำถามเป็นแกนแยก

"ค่าส่งกี่บาทคะ" = ราคา + การจัดส่ง + เป็นคำถาม พร้อมกัน
ผลรวมของทุกหัวข้อจึงไม่เท่ากับจำนวนคอมเมนต์ — บอกไว้บนหน้าจอแล้ว

### 4. แฟนตัวยงกับผู้ชมทับซ้อน **ไม่กรองตามคำค้น**

สองอย่างนี้ตอบคำถาม "ใครคือขาประจำของเพจนี้" ซึ่งไม่เกี่ยวกับคำที่กำลังค้นอยู่
ถ้ากรองด้วย ตัวเลขจะกลายเป็น "ใครพูดคำนี้บ่อยสุด" ซึ่งเป็นคนละคำถาม

### 5. ⚠️ ผู้ชมทับซ้อนข้ามเพจจับด้วย **ชื่อ** เท่านั้น

Meta ให้ `id` ของคนคอมเมนต์เป็น **page-scoped id** — คนเดียวกันได้รหัสคนละตัว
ในแต่ละเพจโดยตั้งใจ (มาตรการความเป็นส่วนตัว)

| ขอบเขต | จับ "คนเดียวกัน" ด้วย |
|---|---|
| ในเพจเดียวกัน | รหัส → แม่นยำ |
| ข้ามเพจ | ชื่อ → **ค่าประมาณขอบบน** |

คำเตือนนี้ติดไปกับผลลัพธ์ในโค้ด (`OverlapResult.caveatTh`) และแสดงบนหน้าจอเสมอ
มีเทสต์ล็อกว่าคำเตือนต้องมีอยู่

## ที่ตรวจเจอตอน audit

รัน `pnpm build && node packages/listening/audit-topics.mjs`

### ⚠️ เจอ false positive จริง 1 อัน

ยิงคอมเมนต์ธรรมดาที่คนไทยพิมพ์กันจริง 37 อัน แล้วดูว่ามีอันไหนถูกจัดหมวดผิด:

> **"จองไว้ในใจ" → อยากซื้อ/สั่งของ**

เป็นสำนวนที่แปลว่า "ประทับใจไว้แล้ว" ไม่ใช่การจองของ — เพิ่มเข้าวลียกเว้นแล้ว
พร้อมเทสต์ล็อกไว้ทั้งสองทาง ("จองไว้ในใจ" ไม่นับ · "จองไว้ 2 ชิ้นค่ะ" ยังนับ)

### ⚠️ เจอของค้าง 15 อันในลิสต์วลียกเว้น

`ขอบคุณ` `ขอบพระคุณ` `ขอบใจ` `ขอโทษ` `ขออนุญาต` `ขอให้` `ขอแสดงความยินดี`
`ช้าง` `เสียง` `เสียใจ` `เสียดาย` `เสียสละ` `ส่งเสริม` `ส่งท้าย` `ส่งเสียง`

วลีพวกนี้**ไม่ได้กันอะไรเลย** เพราะคำที่มันเคยกัน (`ขอ` `ช้า` `เสีย` `ส่ง`)
ถูกตัดออกจากรายการคำสำคัญไปตั้งแต่แรกด้วยเหตุผลเรื่องความกำกวม

ไม่ทำให้ผลผิด แต่:
- กิน CPU ทุกครั้งที่จัดหมวด (คำละหนึ่ง `split/join` × จำนวนคอมเมนต์)
- **หลอกคนอ่านโค้ดว่ามีการป้องกันอยู่ทั้งที่ไม่มี**

เอาออกแล้ว → เร็วขึ้น **28%** (368 ms → 266 ms ต่อ 20,000 คอมเมนต์)
และเพิ่มเทสต์ที่บังคับกฎ "ทุกวลียกเว้นต้องกันคำสำคัญหรือคำถามจริง" ไว้ถาวร

> เทสต์เดิมที่เขียนไว้ว่า `"ขอบคุณ" ต้องไม่ถูกนับเป็นอยากสั่งของ` **ยังผ่านอยู่**
> หลังเอาวลียกเว้นออก เพราะมันผ่านด้วยเหตุผลอื่น (ไม่มีคำ `ขอ` ในลิสต์)
> — เทสต์ที่ผ่านด้วยเหตุผลที่เราไม่ได้ตั้งใจคือเทสต์ที่ไม่ได้ป้องกันสิ่งที่คิดว่าป้องกัน

### ⚠️ ตัว audit เองก็ผิดรอบแรก

รอบแรกเทียบวลียกเว้นกับ `TOPICS` อย่างเดียว **ลืม `QUESTION_MARKERS`**
จึงรายงานว่า `ผ้าไหม` `ไหมพรม` `ไหมขัดฟัน` `เส้นไหม` เป็นของค้าง
ทั้งที่มันกันคำถาม `ไหม` อยู่จริง — ถ้าเชื่อรายงานแล้วลบทิ้ง "ผ้าไหมสวยมาก"
จะกลายเป็นคำถามทันที บันทึกไว้ในโค้ดกันหลงซ้ำ

### ✅ ยิงหน้าเว็บจริงด้วยคอมเมนต์ไทย

ใส่คอมเมนต์จริงแบบที่เจอในเพจขายของ (รวมกับดักคำซ้อน) แล้วยิงหน้า:

- หมวดครบทั้ง 6 · นับคำถามพร้อม % · บอกจำนวนที่ไม่เข้าหัวข้อ
- ค้นคำ **"ปลาร้า"** → เจอเฉพาะคอมเมนต์ที่มีคำนั้น · คอมเมนต์อื่นไม่ติดมา
- **แฟนตัวยงยังครบตอนค้นคำ** (ยืนยันว่าไม่ถูกกรองตามคำค้นตามที่ออกแบบ)
- ค้นคำที่ไม่มี → บอกว่าไม่เจอ ไม่ใช่หน้าว่าง
- กรองตามเพจได้ · แบ่งหน้าได้ · ทุกหน้าเดิมยังคืน 200 · ไม่มี error
