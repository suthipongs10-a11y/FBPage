## 2. บั๊กที่ audit เจอ

### 2.1 แฮชแท็กไทยสะกดผิดทุกอัน (ร้ายแรงที่สุดในรอบนี้)

`toHashtag()` ใช้ `replace(/[^\p{L}\p{N}]/gu, "")` เพื่อตัดช่องว่างกับอีโมจิ
ปัญหาคือ **วรรณยุกต์และสระบน/ล่างของไทยเป็น Unicode Mark (`\p{M}`) ไม่ใช่
Letter (`\p{L}`)** จึงถูกตัดทิ้งไปด้วย

```
"#ร้านกาแฟ"        → "#รานกาแฟ"
"#ข้าวกล่องส่งฟรี"  → "#ขาวกลองสงฟร"
```

และ regex ที่ใช้ดึงแท็กออกจากแคปชั่น (`/#[\p{L}\p{N}_]+/gu`) ก็หยุดที่ตัวแรก
ที่เจอวรรณยุกต์ — `"#ข้าวกล่อง"` ถูกดึงออกมาแค่ `"#ข"` แล้วเหลือ `"้าวกล่อง"`
ค้างอยู่ในเนื้อโพสต์ที่ลูกค้าเห็น

ทำไมอันตราย: มันไม่ crash ไม่มี error และคนที่ไม่ได้อ่านแท็กทีละตัวจะไม่เห็น
มันจะขึ้นเพจลูกค้าไปเรื่อยๆ จนลูกค้าเป็นคนทัก

**แก้:**
- เก็บ `\p{M}` ไว้ทั้งใน `toHashtag()` และ regex ดึงแท็ก
- ตัดความยาวด้วย `Intl.Segmenter` (grapheme) ไม่ใช่ `.slice()` ตาม code unit
  — ไม่งั้นตัดตรงกลางแล้ววรรณยุกต์ขาดจากพยัญชนะ
- เกณฑ์ "สั้นเกินไป" นับเฉพาะ `\p{L}\p{N}` — `"ก้"` คือหนึ่งตัวอักษร ไม่ใช่สอง
- ตัดวรรณยุกต์ที่ลอยอยู่หน้าสุดโดยไม่มีพยัญชนะรองรับ

เพิ่มเทสต์ 3 ตัวที่ล็อกพฤติกรรมนี้ไว้

### 2.2 เสาหลักเลื่อนเมื่อ AI เขียนซ้ำ

`buildMonthCalendar` จับคู่ `slots[i]` กับ `generated.posts[i]` ด้วย index ตรงๆ
แต่ `generateBatch` **ตัดโพสต์ที่ซ้ำกันเองออก** จำนวนจึงไม่ตรงกับแผน

ผลคือถ้าโพสต์ลำดับที่ 2 โดนตัด โพสต์ลำดับ 3 จะเลื่อนมาอยู่ช่องที่ 2
แล้วขึ้นในปฏิทินว่าเป็นเสา "ขาย" ทั้งที่ถูกสร้างมาเป็น "ให้ความรู้" —
สัดส่วนที่แสดงผิดไปทั้งเดือน ซึ่งทำลายคุณค่าหลักของฟีเจอร์ Content Pillars

**แก้:** เชื่อค่า `pillar` ที่ติดมากับตัวโพสต์เอง (ถูกต้องเสมอ)
ส่วนช่องที่ไม่มีโพสต์ ใช้เสาที่ **เหลือจากแผน** (multiset difference)
เพื่อบอกคนเขียนว่าควรเขียนแนวไหน และคำนวณ `mix` จาก entries จริง
ไม่ใช่จากแผนที่ขอไป

### 2.3 Best Time กระจุกวันเดียวแล้วยัดทั้งหมดลงวันนั้น

`buildWeeklySlots` เชื่อคะแนนของ Best Time ล้วน กันแค่ช่วงห่างระหว่างโพสต์
เพจที่โพสต์วันพฤหัสทุกสัปดาห์ (พบบ่อยมากในลูกค้าจริง) จะมีคะแนนสูงสุด 5 อันดับแรก
อยู่วันพฤหัสหมด → ตารางกลายเป็นโพสต์พฤหัส 5 ครั้งแล้วเงียบอีกหกวัน
ซึ่งแย่กว่าไม่ตั้งเวลาเลย

**แก้:** เพิ่ม `MAX_POSTS_PER_DAY = 2` เข้าไปในเงื่อนไข `conflicts()`

### 2.4 `rescheduleEntry` คืนแค่รายการ ทำให้ช่วงวันที่ค้าง

คืน `entries` อย่างเดียว แต่ `ContentCalendar` มี `startAtMs`/`endAtMs`
คนเรียกที่เอา entries ไปแปะทับจะถือปฏิทินที่ช่วงวันที่ผิดโดยไม่รู้ตัว

**แก้:** คืน `calendar` ทั้งก้อนที่คำนวณ `startAtMs`/`endAtMs` ใหม่แล้ว
(ล้มเหลว = คืนตัวเดิมไม่แตะ)

### 2.5 `sanitizeText` ระเบิดถ้า `pageId` ว่าง

`new RegExp("")` ตรงกับ **ทุกตำแหน่ง** ในสตริง — จะยัด `[[ชื่อร้าน]]`
แทรกระหว่างตัวอักษรทุกตัวของทั้งเทมเพลต

**แก้:** เช็คว่าไม่ว่างก่อนแทนที่

### 2.6 ตัวแปรที่ไม่ได้อยู่ในรายการ `placeholders` หลุดถึงลูกค้าได้

`assertFilled()` เชื่อฟิลด์ `placeholders` ที่คำนวณตอนถอดเทมเพลต
แต่เทมเพลตที่แก้ใน DB หรือเขียนมือ อาจมีตัวแปรที่ไม่ได้อยู่ในรายการนั้น
ผลคือบอทจะพิมพ์ `[[เบอร์โทร]]` ให้ลูกค้าอ่าน

**แก้:** เพิ่ม `assertNoPlaceholdersLeft()` สแกน JSON ของผลลัพธ์สุดท้าย
ก่อนคืนออกไปทุกเส้นทาง (flow / rules / plan)

## 3. จุดที่ออกแบบให้ล้มไว้ก่อน (โดยเจตนา)

### 3.1 Recycle 60 วัน ปะทะ Duplicate Guard 90 วัน

สเปกสั่ง recycle หลัง 60 วัน แต่ Duplicate Guard ของ M-B บล็อกเนื้อหาซ้ำภายใน 90 วัน
ถ้าเขียนใหม่ไม่ต่างพอ ระบบจะบล็อกโพสต์ของตัวเอง แล้วคนจะงงว่าทำไมกด recycle แล้วไม่ขึ้น

`rewriteForRecycle()` จึง **พิสูจน์สองชั้น** ก่อนคืนผลลัพธ์:
1. hash ต้องไม่ตรงของเดิม (ถ้าตรง = โดนบล็อกแน่นอน)
2. ต้องต่างจากเดิม ≥ 40% (Jaccard บน 4-gram — ใช้ n-gram เพราะไทยไม่เว้นวรรค)

ลองใหม่ได้ 3 ครั้งพร้อมคำสั่งที่เข้มขึ้นเรื่อยๆ ถ้ายังไม่ผ่าน `safeRepostDate()`
จะคืน 90 วันแทน 60 วัน พร้อมข้อความไทยที่บอกว่าทำไม

### 3.2 Template Library ล้มไว้ก่อนเมื่อสงสัยว่าข้อมูลรั่ว

ฟีเจอร์นี้เอาของจากลูกค้ารายหนึ่งไปวางที่อีกราย ถ้าหลุดครั้งเดียว
— เบอร์ร้านเก่าไปโผล่ในบอทร้านใหม่ — จบความสัมพันธ์กับลูกค้าทั้งสองรายพร้อมกัน

ด่านที่วางไว้:
- แทนที่ของที่ประกาศไว้ (ชื่อร้าน เบอร์ ลิงก์ ไลน์ รหัสเพจ) ด้วยตัวแปร
  โดยเบอร์จับแบบหลวม (`081-234-5678` = `081 234 5678` = `0812345678`)
  และแทนคำยาวก่อนคำสั้นเพื่อไม่ให้เหลือเศษชื่อร้านเดิม
- **สแกนซ้ำทั้งก้อน** หาเลขยาว ≥ 9 หลัก (จับทั้งเบอร์และรหัสเพจ 15 หลัก
  ที่ `detectPhone` ของ M3 จับไม่ได้), ลิงก์ทุกชนิด, ไอดี `@...`
- เจออะไรที่ยังน่าสงสัย = **ไม่ยอมสร้างเทมเพลต** พร้อมบอกว่าเจอที่ฟิลด์ไหน
  และต้องแก้ยังไง ไม่ใช่แค่เตือน

**จงใจไม่ใช้ `detectExternalLink()` ของ M3** เพราะตัวนั้นถือว่า `facebook.com`
และ `m.me` เป็นลิงก์ปลอดภัย (ถูกสำหรับคอมเมนต์) แต่ในเทมเพลต `m.me/ร้านเก่า`
คือการส่งลูกค้าใหม่ไปแชทกับร้านเก่า ซึ่งแย่ที่สุดในบรรดาลิงก์ทั้งหมด

### 3.3 ตัวแปรเทมเพลตใช้ `[[...]]` ไม่ใช่ `{...}`

`{...}` ถูกจองไว้แล้วโดย `renderTemplate()` ของ M3 สำหรับตัวแปรตอนรันจริง
(`{ชื่อลูกค้า}` = ชื่อคนที่คอมเมนต์) ถ้าใช้วงเล็บชุดเดียวกัน การกรอกเทมเพลต
จะไปกินตัวแปรรันไทม์ทิ้ง แล้วบอทจะทักลูกค้า **ทุกคน** ด้วยชื่อเดียวกัน

มีเทสต์ที่ยืนยันว่า `{ชื่อลูกค้า}` รอดผ่านการกรอกเทมเพลตแล้วยัง render ได้จริง

### 3.4 ของที่ก๊อปมาปิดไว้ก่อนเสมอ

`applyBotFlowTemplate()` / `applyModerationTemplate()` ตั้ง `isActive: false`
เป็นค่าเริ่มต้น — เทมเพลตที่เพิ่งก๊อปมาต้องมีคนอ่านก่อนคุยกับลูกค้าจริง

### 3.5 ไม่สร้างปฏิทินจาก Brand Brief ที่ยังกรอกไม่ครบ

`buildMonthCalendar()` ปฏิเสธตั้งแต่ต้นพร้อมบอกว่าขาดอะไร
เจตนา ไม่ใช่ความขี้เกียจ: ปล่อยให้สร้างจาก brief ครึ่งๆ = ได้โพสต์กลางๆ 20 อัน
ที่ต้องแก้ทุกอัน ซึ่งช้ากว่าเขียนเองตั้งแต่แรก

### 3.6 ไม่สุ่มเสาหลัก

`distributePillars()` ใช้ largest remainder + การกระจายแบบ Sainte-Laguë
ไม่ใช่การสุ่ม — เพราะการสุ่มจริงทำให้บางเดือนได้โพสต์ขาย 8 วันติด
ซึ่งแย่กว่าไม่ตั้งสัดส่วนเลย มีเทสต์ยืนยันว่าประเภทเดียวกันไม่ติดกันเกิน 2 ช่อง
และกดสองครั้งได้แผนเดียวกัน

## 4. สิ่งที่ยังไม่ทำและเหตุผล

| สิ่งที่สเปกสั่ง | ทำไมยังไม่ทำ |
|---|---|
| สร้างภาพประกอบ (Gemini/GPT Image) | สเปกบอกว่า "ต่อกับ pipeline ภาพที่คุณมี" — ต้องรู้ก่อนว่า pipeline เดิมมี interface อะไร ไม่งั้นได้ abstraction ที่ต้องรื้อ |
| Reels/วิดีโอสั้น (Remotion) | เหตุผลเดียวกัน + Reels API ต้องผ่าน App Review แยก |
| ตัววาด flow / หน้าปฏิทิน (UI) | เป็นงาน `apps/web` ตรรกะฝั่งหลังบ้านพร้อมหมดแล้ว (`groupByLocalDate`, `describeCalendar`, `rescheduleEntry` ออกแบบมาให้ drag & drop ใช้ได้เลย) |
| เก็บเทมเพลตลง DB | ต้องมี Prisma repository ก่อน — ตอนนี้ `Template` เป็น plain object ที่ serialize ได้ตรงๆ |
