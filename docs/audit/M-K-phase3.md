## เรื่องที่ต้องตัดสินใจ แล้วตัดสินใจแบบไหน

### 1. โหลดโพสต์มาคำนวณใน JS แทนที่จะ `GROUP BY` ใน SQL

สูตรนับ engagement กับส่วนแบ่งเสียงอยู่ใน `packages/listening` ซึ่งมีเทสต์ครอบแล้ว
ถ้าเขียน SQL รวมยอดอีกชุด จะมี**สูตรสองที่ที่ต้องตรงกันเอง** — วันหนึ่งจะเพี้ยน
แล้วไม่มีใครรู้ว่าอันไหนถูก

ขนาดข้อมูลรองรับสบาย: เพดาน 100 โพสต์/เพจ × 10–20 เพจ ≈ สองพันแถว

### 2. คู่แข่งตั้ง `source = EXTERNAL` ให้อัตโนมัติ

ดึงเพจที่เราไม่ได้เป็นแอดมินต้องมีสิทธิ์ **Page Public Content Access**
ถ้าตั้งเป็น `META_API` ระบบจะยิงทุกชั่วโมงแล้วโดนปฏิเสธทุกชั่วโมง เปลืองโควตา
ที่ใช้ร่วมกับงานที่ลูกค้ารออยู่ โดยไม่ได้อะไรกลับมาเลย

ฟอร์มจึงบอกตรงๆ ตั้งแต่ก่อนกดเพิ่มว่าเพจแบบนี้จะยังไม่มีตัวเลข

### 3. เลือกคู่เทียบผ่าน query string ไม่ใช่ state ฝั่ง client

ลิงก์ที่เลือกไว้แล้วต้องส่งให้คนอื่นดูได้ และปุ่มย้อนกลับต้องกลับไปคู่ที่แล้วจริงๆ

### 4. หน้าจอ **ต้อง**แสดง "กี่เท่า" คู่กับเปอร์เซ็นต์

ข้อบังคับที่มาจาก `docs/audit/M-K-phase1.md` — `contributionPct` เป็นหน่วย
ลอการิทึมที่ปรับสเกลแล้ว ผู้ติดตามมากกว่า 5.9 เท่าออกมาเป็น +138.9%
คนอ่านจะแปลเป็น 2.4 เท่าซึ่งผิด ทุกบรรทัดจึงมี `(5.9 เท่า)` กำกับ
และมีประโยคอธิบายท้ายกล่องว่าเปอร์เซ็นต์นี้คือ "มีส่วนในช่องว่างเท่าไร"

## ที่ตรวจเจอตอน audit

### ✅ ยิงหน้าเว็บจริงด้วยข้อมูลชุดเดียวกับหน้าจอต้นแบบ

ใส่ข้อมูล 4 เพจที่ engagement ตรงกับภาพต้นแบบเป๊ะ แล้ววัดผลลัพธ์บนหน้าจริง:

| ค่าที่หน้าจอแสดง | ต้นแบบ | เราได้ |
|---|---|---|
| ซ้อก้าด | 58.4% | **58.4%** |
| Pimrypie | 34.8% | **34.8%** |
| ไบรท์ไร้ไขมัน | 3.9% | **3.9%** |
| LOVEPOTION | 2.9% | **2.9%** |
| โพสต์ถี่กว่า | +11.8% | **+11.8%** |
| ผู้ติดตามมากกว่า | +138.9% | **+138.8%** |
| คอนเทนต์โดนใจน้อยกว่า | −191.1% | **−191.1%** |

ตรวจซ้ำว่าสามบรรทัดรวมกันเท่าพาดหัวบนหน้าจอจริง: `11.8 + 138.8 − 191.1 = −40.5` ✓

> ต่างจากต้นแบบ 0.1% ที่บรรทัดผู้ติดตาม เพราะข้อมูลทดสอบใช้ยอด engagement
> ของแดชบอร์ด (4,288,923) ส่วนภาพหน้าเทียบเพจของต้นแบบใช้ช่วงวันที่อื่น (4,281,108)

### ✅ หน้าอื่นไม่พัง

`/` `/settings` `/ops` `/calendar` `/inbox` ยังคืน 200 ทั้งหมด · ไม่มี error ในเทอร์มินัล

### ⚠️ เจอบั๊กจริง 1 จุด (แก้แล้ว)

**ลิงก์ "เทียบกับตัวเอง"** — ปุ่มเลือก "เพจของเรา" แสดงทุกเพจรวมถึงเพจที่กำลังอยู่
ฝั่ง "เทียบกับ" ทำให้เกิดลิงก์ `?ours=X&theirs=X`

โค้ดหน้ารับมือได้ (เด้ง `theirs` ไปเป็นคู่แข่งที่แรงที่สุดแทน ไม่ crash)
แต่ผลคือ **คนกดจะเห็นผลลัพธ์ที่ไม่ได้ขอโดยไม่รู้ว่าทำไม**

แก้เป็น: กดเพจที่อยู่ฝั่งตรงข้าม = **สลับข้าง** ซึ่งเป็นสิ่งที่คนคาดหวังอยู่แล้ว
ตรวจซ้ำแล้วว่าลิงก์บนหน้าไม่มีคู่ที่ `ours === theirs` เหลืออยู่เลย (0 จาก 7 ลิงก์)
