## เรื่องที่ต้องตัดสินใจ แล้วตัดสินใจแบบไหน

### 1. `engagement` นับตามวันที่โพสต์ ไม่ใช่วันที่คนกด

Meta ให้ยอดรีแอ็กชันมาเป็น "ยอดรวม ณ ตอนที่ดึง" ไม่มี timestamp รายรีแอ็กชัน
ถ้าจะนับตามวันที่คนกด ต้องเก็บ snapshot ถี่ๆ แล้วหาผลต่าง ซึ่งพลาดง่ายและ
ข้อมูลย้อนหลังจะไม่มีวันถูก

**ผลข้างเคียงที่ต้องรู้:** โพสต์ที่เพิ่งลงยังเก็บ engagement ไม่ครบ ตัวเลขของช่วง
ที่ชนขอบวันนี้จึงต่ำกว่าความจริงเสมอ — เทียบข้ามเพจได้ (ทุกเพจโดนเท่ากัน)
แต่เทียบข้ามช่วงเวลาต้องระวัง

### 2. ช่วงเวลาเป็นครึ่งเปิด `[start, end)`

ถ้าปิดสองข้าง โพสต์ที่ลงเที่ยงคืนวันที่ 1 พอดีจะถูกนับทั้งเดือนก่อนและเดือนถัดไป
มีเทสต์ล็อกขอบทั้งสองด้านไว้แล้ว

### 3. แยกตาราง `tracked_*` ออกจาก `pages` / `posts` / `comments` เดิม

ตารางเดิมคือ "เพจที่เราดูแล" — มี token แก้ไขได้ ส่วนชุดใหม่คือ "เพจที่เราเฝ้าดู"
ซึ่งรวมคู่แข่งที่เราไม่ได้เป็นแอดมิน

ถ้ารวมตารางเดียวกัน ทุกจุดที่วนลูป `pages` เพื่อทำงาน (ยิงโพสต์ ตอบแชท ต่ออายุ token)
จะเจอเพจคู่แข่งปนเข้ามา ต้องไปเติมเงื่อนไขกรองทีละจุด — **พลาดจุดเดียวคือพยายาม
โพสต์ลงเพจชาวบ้าน**

## สูตรแยกช่องว่าง — ถอดจากเครื่องมือต้นแบบได้ตรงเป๊ะ

```
E = P × F × q                     q = E / (P × F)  ← คุณภาพคอนเทนต์
ln(E₁/E₂) = ln(P₁/P₂) + ln(F₁/F₂) + ln(q₁/q₂)      ← บวกกันได้พอดี
scale = gapPct / ln(E₁/E₂)                          ← ปรับให้ลงตัวกับพาดหัว
```

ยืนยันด้วยตัวเลขจริงจากหน้าจอต้นแบบ (เทสต์ `ให้ผลตรงกับตัวเลขอ้างอิง`):

| | ค่าจากหน้าจอต้นแบบ | ที่เราคำนวณได้ |
|---|---|---|
| ช่องว่างรวม | −40.4% | −40.4% |
| โพสต์ถี่กว่า | +11.8% | +11.8% |
| ผู้ติดตามมากกว่า | +138.9% | +138.9% |
| คอนเทนต์โดนใจน้อยกว่า | −191.1% | −191.1% |

## ที่ตรวจเจอตอน audit

### ✅ ยิงข้อมูลสุ่ม 500,000 เคส

| สิ่งที่ตรวจ | ผล |
|---|---|
| สามบรรทัดรวมกันเท่าพาดหัว | คลาดสูงสุด **3.75e-16** (ระดับปัดเศษ double) |
| คุณภาพคอนเทนต์ = `E/(P×F)` ที่คิดตรงๆ | คลาดสูงสุด 5.38e-15 |
| เครื่องหมายตรงกับทิศของอัตราส่วน | ผิด **0** เคส |
| `NaN` / `Infinity` | **0** เคส |

### ⚠️ เจอกับดักการนำเสนอ (แก้แล้วด้วยเอกสาร + เทสต์)

`contributionPct` **ไม่ใช่** "มากกว่า/น้อยกว่ากี่เปอร์เซ็นต์" — มันคือส่วนแบ่งของ
ช่องว่างในหน่วยลอการิทึม ค่าเกิน ±100% เป็นเรื่องปกติ

- ผู้ติดตามมากกว่า **5.9 เท่า** → แสดงเป็น **+138.9%**
  คนอ่านจะแปลว่า "มากกว่า 2.4 เท่า" ซึ่ง**ผิด**
- เคสสุดขั้วที่เจอตอนสุ่ม: ต่างกัน **474 เท่า** → **−616%**

**ข้อบังคับสำหรับ Phase 3:** หน้าจอต้องแสดง `ratio` ควบคู่กับ `contributionPct` เสมอ
มีเทสต์ล็อกไว้แล้วว่า `ratio` ต้องมีและตรงกับความจริง

### ⚠️ ข้อผิดพลาดของตัว audit เอง (บันทึกไว้กันหลงซ้ำ)

รอบแรกวัดด้วย **relative error** เทียบกับผลลัพธ์ แล้วได้ 22.7% ดูเหมือนบั๊กใหญ่
ที่จริงคือเคสที่ engagement สองฝั่งเท่ากันเป๊ะ → `gapPct = 0` → หารด้วยศูนย์
ความคลาดจริงคือ **2.27e-13** บนตัวเลขขนาด 1,228 (หนึ่ง ULP)

เกณฑ์ที่ถูกคือเทียบกับ **ผลรวมขนาดของตัวเลขที่เอามาบวกกัน** ไม่ใช่เทียบกับผลลัพธ์
— ผลลัพธ์ที่เป็นศูนย์ทำให้ relative error ไร้ความหมายเสมอ
