## 2. บั๊กที่ audit เจอ

### 2.1 คำตอบจากกฎเรียกชื่อลูกค้าไม่ได้

`matchRules()` ส่ง `{ชื่อลูกค้า: undefined}` เข้า `applyTone` แบบตายตัว
ทั้งที่ `ctx.contactName` มีอยู่ ผลคือกฎที่เขียนว่า `สวัสดีค่ะ {ชื่อลูกค้า}`
จะได้ `สวัสดีค่ะ` เสมอ — ฟีเจอร์ตัวแปรที่สเปกสั่งไว้ใช้ไม่ได้จริงในชั้นที่ 1
ซึ่งเป็นชั้นที่ตอบลูกค้าเยอะที่สุด

**แก้:** ส่ง `contactName` ผ่านเข้าไป

### 2.2 dynamic import กลางฟังก์ชันโดยไม่จำเป็น

`answerWithRag` ทำ `await import("./tone.js")` เพื่อเอา `buildSystemPrompt`
ทั้งที่ไฟล์เดียวกันนั้น import แบบปกติอยู่แล้วด้านบน — เพิ่ม latency
ทุกครั้งที่เรียก LLM โดยไม่ได้อะไรตอบแทน

**แก้:** import แบบปกติ

### 2.3 Test Console ทำข้อมูลที่ flow เก็บมาหาย

`dryRunFlow` อ่านตัวแปรจาก `state.variables` แต่พอ flow จบ `state` เป็น `null`
ตัวแปรที่เก็บได้ในขั้นสุดท้ายจึงหายไป

เรื่องนี้สำคัญกว่าที่เห็น: flow เก็บ lead คือ flow ที่ **ข้อมูลตอนจบคือผลลัพธ์**
(ชื่อ เบอร์ ที่อยู่) การรัน test console แล้วเห็นว่า "ที่อยู่" หายไปทั้งที่ flow
ถามไปแล้ว จะทำให้คนตั้งค่าเข้าใจผิดว่า flow พัง

**แก้:** เพิ่มฟิลด์ `variables` ใน `FlowStepResult` แยกจาก `state`
ข้อมูลที่เก็บมาจึงไม่หายแม้ flow จะจบแล้ว

## 3. ฟีเจอร์ที่สเปกสั่งแต่ยังไม่มี (เพิ่มแล้ว)

### 3.1 Flow engine (`flow.ts`)

รองรับ node ครบตามที่สเปกระบุ ยกเว้น webhook (ดูข้อ 5)

จุดที่คิดเพิ่มจากสเปก:
- **จำกัดจำนวนขั้นต่อรอบ** — flow ที่ลูกค้าวาดเองอาจมีวงวน (A → B → A)
  โดยไม่ตั้งใจ ถ้าไม่จำกัด บอทจะยิงข้อความรัวใส่ลูกค้าจนโดนบล็อก
  ตอนนี้เดินเกิน 10 ขั้นแล้วส่งต่อให้คนแทน
- **`validateFlow()`** ตรวจก่อนเปิดใช้: node ปลายทางมีจริงไหม, มี node
  ที่เข้าไม่ถึงไหม (ลืมต่อเส้น), ตัวเลือกที่ไม่มีตัวเลือก
  เจอปัญหาตอนตั้งค่าดีกว่าตอนลูกค้ากำลังคุย
- **ลูกค้าตอบไม่ตรงตัวเลือก → ถามใหม่** ไม่เดินต่อมั่ว
- **`stepFlow` ไม่แก้ state เดิม** ส่ง state เดิมเข้าไปซ้ำได้ผลเดิมเสมอ

### 3.2 Messenger Profile (`messenger-profile.ts`)

ตรวจข้อจำกัดของ Meta เองก่อนยิง (Ice Breakers ≤ 4 ข้อ, เมนู ≤ 3 ปุ่ม,
ความยาวคำถาม) เพราะ error ของ Meta เรื่องนี้อ่านยากมาก

`suggestIceBreakers()` เสนอคำถามจากกฎชั้น 1 ที่เพจตั้งไว้ — เหตุผลคือ
คำถามที่โชว์ควรเป็นคำถามที่บอท **ตอบได้แน่นอน** ถ้าโชว์คำถามที่ต้องพึ่ง LLM
ลูกค้ากดแล้วอาจได้ "รอสักครู่นะคะ" ตั้งแต่ข้อความแรก ซึ่งดูแย่มาก

ไม่ปิดช่องพิมพ์ (`composer_input_disabled: false`) เสมอ — ปิดแล้วลูกค้า
ที่อยากถามอย่างอื่นจะติดตัน

### 3.3 Test Console (`dryRunFlow`)

ป้อนลำดับข้อความที่ลูกค้าจะพิมพ์ แล้วดูว่าบอทตอบอะไรและเก็บตัวแปรอะไรได้บ้าง
โดยไม่ส่งจริง

## 4. กฎที่บังคับในโค้ด ไม่ใช่แค่หวังว่า prompt จะพอ

| กฎ | บังคับยังไง |
|---|---|
| กฎข้อ 7: บอทห้ามใช้ HUMAN_AGENT | เรียก `decideSend({sentBy: "bot"})` ก่อนตอบทุกครั้ง — บอทไม่มีทางระบุ tag เองได้ |
| ตอบจากข้อมูลจริงเท่านั้น | ไม่เจอ chunk เลย → **ไม่เรียก LLM** เพราะเรียกไปก็ได้แต่คำตอบที่แต่งขึ้น |
| ไม่ข้ามเพจ | `retrieve()` กรอง `pageId` เสมอ มีเทสต์ยืนยันว่าข้อมูลเพจอื่นไม่หลุดเข้า context |
| คำต้องห้ามของเพจ | ตรวจ **หลัง** LLM ตอบ และตรวจแม้คำตอบมาจากกฎที่คนเขียนเอง |
| ประกาศว่าเป็นบอท | ข้อความแรกเสมอ พร้อมบอกวิธีขอคุยกับคน |
| ลูกค้าขอคุยกับคน | ข้ามทุกชั้นทันที ไม่ให้บอทตื๊อ |

**เหตุผลที่ตรวจคำต้องห้ามหลัง LLM:** โมเดลไม่ทำตามคำสั่ง 100%
และคำต้องห้ามส่วนใหญ่มีเหตุผลทางกฎหมาย (เพจคลินิกห้ามพูดว่า "รักษาหายขาด")
การหวังว่า system prompt จะพอคือการเดิมพันด้วยใบอนุญาตของลูกค้า

**เหตุผลที่ตรวจแม้คำตอบมาจากกฎ:** คนเขียนกฎก็เผลอได้ และกฎถูกเขียนครั้งเดียว
ใช้ยาวเป็นปี

## 5. สิ่งที่ตั้งใจไม่ทำตอนนี้

**node เรียก webhook ใน flow** — สเปกระบุไว้ แต่การให้ flow ยิง HTTP
ไปที่ไหนก็ได้เปิดช่อง SSRF (คนตั้งค่าชี้ไปที่ metadata endpoint ของ VPS ได้)
ต้องออกแบบ allowlist ปลายทาง + timeout + จำกัดขนาด response ก่อน
ทำแบบครึ่งๆ กลางๆ อันตรายกว่าไม่ทำ

**Flow Builder UI (React Flow)** — ตัวรันและตัวตรวจพร้อมแล้ว รอ `apps/web`

**Embedding จริง** — `Embedder` เป็น interface, ระบบทำงานได้ด้วยการจับคำ
ระหว่างที่ยังไม่ต่อ ต้องเลือกผู้ให้บริการ (สเปกเสนอ `text-embedding-004`
หรือ bge-m3) และมิติต้องตรงกับ schema `vector(768)`

## 6. สิ่งที่ต้องระวังต่อไป

1. **`MAX_STEPS_PER_TURN` คือกันชนเดียวที่กันบอทยิงรัว** — เพิ่ม node ชนิดใหม่
   ที่เดินต่อได้เองต้องนับรวมในลูปนี้ด้วย
2. **`retrieve()` กรอง pageId** — เพิ่มเส้นทางค้นข้อมูลใหม่ต้องกรองเหมือนกัน
   ข้อมูลลูกค้ารั่วข้ามเพจคือความเสียหายที่กู้ไม่ได้
3. **ตรวจคำต้องห้ามต้องอยู่หลังสุดเสมอ** — ถ้ามีชั้นที่ 4 เพิ่มมา
   ต้องผ่าน `guard()` ด้วย
