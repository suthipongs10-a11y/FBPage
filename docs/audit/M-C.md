## 2. บั๊กที่ audit เจอ และแก้แล้ว

### 2.1 รายการคำหยาบทำให้เพจสัตว์เลี้ยงพัง (ร้ายแรงที่สุด)

รายการเดิมมีคำว่า `"สัตว์"` และ `"กู"` ภาษาไทยไม่เว้นวรรคระหว่างคำ
การแมตช์จึงเป็น substring ล้วน ผลคือ:

| คอมเมนต์ลูกค้าจริง | ผลที่เกิด |
|---|---|
| "รับฝากสัตว์เลี้ยงไหมคะ" | ถูกซ่อน |
| "อาหารสัตว์ราคาเท่าไหร่" | ถูกซ่อน |
| "มีสัตวแพทย์ประจำไหมคะ" | ถูกซ่อน |
| "หาในกูเกิลได้เลยค่ะ" | ถูกซ่อน |

นี่คือความเสียหายที่ **มองไม่เห็น** — ลูกค้าไม่รู้ว่าคอมเมนต์ตัวเองถูกซ่อน
เห็นแต่ว่าเพจไม่ตอบ แล้วเงียบหายไป เจ้าของเพจก็ไม่รู้ว่าเสียลูกค้าไปเพราะอะไร

**แก้:**
- ถอดคำที่กำกวมออก ใส่เฉพาะรูปที่ยาวพอจะไม่ชนคำสุภาพ (`ไอ้สัตว์` แทน `สัตว์`)
- เพิ่ม `PROFANITY_EXCEPTIONS` — ตัดคำสุภาพที่มีคำหยาบเป็นส่วนประกอบออกจาก
  ข้อความก่อนค้นหา (จำเป็นเพราะลูกค้าเพิ่มคำเองได้ เราคุมไม่ได้ว่าจะกำกวมแค่ไหน)
- เทสต์บังคับว่าทุกคำในลิสต์ต้องยาวอย่างน้อย 3 ตัวอักษร

มีไฟล์เทสต์แยก `false-positive.test.ts` ที่รวบรวม "ประโยคที่ลูกค้าจริงพิมพ์"
ซึ่งต้องไม่ถูกซ่อนเด็ดขาด

### 2.2 การแก้ conflict เป็นแบบสมมาตร → คำหยาบไม่ถูกซ่อน

โค้ดเดิมใช้กฎ "ตัวแรกที่วางแผนไว้ชนะ" ซึ่งพังเมื่อลูกค้าตั้ง priority เอง:

```
กฎ "กดไลก์คอมเมนต์เชิงบวก"  priority 5
กฎ "ซ่อนคำหยาบ"             priority 99
```

คอมเมนต์ที่มีทั้งคำชมและคำหยาบ → `like` ถูกวางแผนก่อน แล้ว `hide` ถูกข้าม
เพราะขัดกับ `like` **ผลคือคอมเมนต์หยาบไม่ถูกซ่อน แถมยังได้ไลก์จากเพจ**

**แก้:** เปลี่ยนเป็นลำดับอำนาจแบบไม่สมมาตร (`ACTION_RANK`)
การปกป้องเพจ (delete 100 / hide 90) ชนะการเพิ่ม engagement (like 10) เสมอ
ถ้า action ที่แรงกว่ามาทีหลัง จะถอน action ที่อ่อนกว่าออกจากแผน

## 3. หลักการที่ยึดตลอดโมดูลนี้

### false positive แพงกว่า false negative

- ตัวตรวจจับทุกตัวคืน **ค่าความมั่นใจ** ไม่ใช่ตอบแค่ใช่/ไม่ใช่
- `hide` ต้องมั่นใจ ≥ 80%, `delete` ต้อง ≥ 95% (ลบแล้วกู้ไม่ได้)
- ไม่ถึงเกณฑ์ = ปักธงให้คนดู ไม่ทำเอง
- เลขยาวที่ไม่ตรงรูปแบบเบอร์ไทย → ปักธง ไม่ซ่อน
- `@xxxxx` อาจเป็นการแท็กคน → มั่นใจ 55% ปักธงเท่านั้น

เทสต์ที่ยืนยันเรื่องนี้: ราคา/ไซส์/เวลา/เลขพัสดุ ต้องไม่ถูกจับเป็นเบอร์โทร

### รับมือการหลบ filter ตั้งแต่ต้น

วิธีหลบที่รองรับ (มีเทสต์ทุกอัน): แทรกช่องว่าง/จุดกลางคำ, ซ้ำตัวอักษร,
เลขไทย, ใช้ `o` แทน `0`, อักขระล่องหนที่ copy ติดมา

ข้อควรระวัง: `normalizeAggressive` ลบสระและวรรณยุกต์ออกหมด ซึ่งทำให้คำสั้นชนกันง่าย
จึงจำกัดให้ใช้เฉพาะคำที่ยาว ≥ 3 ตัวหลัง normalize และใช้กับรายการคำหยาบเท่านั้น
**ห้ามเอาไปใช้กับคีย์เวิร์ดทั่วไปที่ลูกค้าตั้งเอง**

### ไม่ใช้ LLM ทำ sentiment

สเปกข้อ M2 วางหลักไว้ว่าอย่าใช้ LLM ตอบทุกข้อความ เหตุผลเดียวกันใช้ที่นี่:
คอมเมนต์วันละหลายพัน และ alert ต้องถึงแอดมินภายใน 1 นาที

จุดที่ระวังเป็นพิเศษในการทำ lexicon ไทย: **คำปฏิเสธ**
`"ไม่ดี"` ต้องไม่ถูกนับเป็นบวกเพราะมีคำว่า `"ดี"` อยู่ข้างใน
และ `"ไม่แย่"` ก็ไม่ได้แปลว่าชม (ปฏิเสธคำลบ ≠ คำชม)

บั๊กที่เจอตอนเขียนเทสต์: เงื่อนไขลดความมั่นใจของคำถามเช็ค `Math.abs(score) < 1`
ทำให้ `"ของดีมากไหมคะ"` (มีแต่คำบวก) ไม่ถูกลดเลย ทั้งที่เป็นคำถาม ไม่ใช่คำชม

## 5. ข้อจำกัดของ Meta ที่จัดการแล้ว

**Private Reply ทำได้ครั้งเดียวต่อคอมเมนต์ ภายใน 7 วัน**

ระบบเช็คทั้งสองเงื่อนไข **ก่อน** ยิงออกไป ไม่ปล่อยให้ Meta ปฏิเสธเอง
เหตุผล: ยิงไปให้โดนปฏิเสธเปลืองโควตาและทำให้ log รกจนหาปัญหาจริงไม่เจอ

จุดที่ละเอียดอ่อน: บันทึกว่า "ทักแล้ว" **เฉพาะเมื่อยิงสำเร็จ**
ถ้าบันทึกก่อนแล้วยิงพลาด ลูกค้ารายนั้นจะไม่มีวันได้รับข้อความอีกเลย
(มีเทสต์คุมข้อนี้ไว้)

## 6. ยังเหลือของ M-C

- **Webhook receiver** — `CommentProcessor.process()` พร้อมรับงานแล้ว
  รอ `apps/webhook` (Fastify) มาเรียก
- **Prisma repository** — `CommentStore` เป็น interface
  schema มี `comments.private_replied_at` และ `fb_comment_id` unique รองรับแล้ว
- **UI ตั้งกฎ** — โครงสร้าง `AutomationRule` รองรับ แต่หน้าจอรอ `apps/web`
- **LINE notifier ตัวจริง** — `ModerationAlertSink` เป็น interface

## 7. สิ่งที่ต้องระวังต่อไป

1. **อย่าเติมคำสั้นๆ ลง `PROFANITY_TH`** — เทสต์บังคับความยาวขั้นต่ำไว้แล้ว
   แต่ถ้าลูกค้าเพิ่มคำเองผ่าน `customProfanity` ระบบคุมไม่ได้
   → ตอน M-H (Client Portal) ควรเตือนในหน้าตั้งค่าว่าคำสั้นเสี่ยงจับผิด
2. **โพสต์ไวรัลที่มีคอมเมนต์ "สนใจ" หลายร้อยอัน** จะยิง private reply เป็นร้อยครั้ง
   gateway คุมอัตราให้แล้ว (คิวต่อเพจ + priority realtime) แต่ควรมีเพดานต่อวัน
   ต่อเพจตอน M-I (Ops Center) กันดูเหมือนสแปม
3. **`ACTION_RANK` คือจุดตัดสินความปลอดภัย** — เพิ่ม action ชนิดใหม่ต้องกำหนด rank
   ให้ถูก ไม่งั้นจะกลับไปมีบั๊กเดิม
