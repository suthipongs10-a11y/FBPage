# apps/web — หอบังคับการ (Control Tower)

Next.js 15 App Router + Tailwind v4

```bash
pnpm --filter @page-os/web dev     # http://localhost:3000
pnpm --filter @page-os/web build
```

## หน้าจอ

| เส้นทาง | หน้าที่ | สเปก |
|---|---|---|
| `/` | Today View — ต้องตอบกี่ข้อความ / อนุมัติกี่โพสต์ / อะไรพัง / SLA ใกล้เกิน | M8 |
| `/inbox` | คิวข้อความเรียงตาม SLA + บทสนทนาที่บอทดูแลอยู่ | M1, M8 |
| `/calendar` | ปฏิทินรวมทุกเพจในจอเดียว สีแยกตามลูกค้า + drag & drop | M4 |
| `/pages` | สถานะ token และ webhook ของทุกเพจ จัดกลุ่มตามลูกค้า | M0 |

## หลักที่ยึดตอนออกแบบ

สเปกข้อ 2 เขียนไว้ว่า **"UI ต้องออกแบบเป็น control tower ไม่ใช่ dashboard สวยๆ ต่อเพจ"**
เพราะผู้ใช้จริงมีคนเดียวและต้องอ่านทั้งวัน หน้าจอนี้จึงเป็นแบบ:

- **สีเงียบเป็นค่าเริ่มต้น** ปล่อยให้ "สิ่งที่ต้องทำ" เป็นของเดียวที่สว่างขึ้นมา
- **ตัวเลขเวลาที่เหลือ ไม่ใช่แค่ป้ายสี** — "เหลือ 6 นาที" ตัดสินใจได้ทันที
  ส่วนป้ายแดงบอกได้แค่ "ด่วน" ซึ่งด่วนเท่ากันหมด
- **บรรทัดเดียวต่อสาเหตุ ไม่ใช่ต่ออาการ** — token เพจหนึ่งหมด โพสต์ล้มพร้อมกันสิบอัน
  ถ้าขึ้นสิบบรรทัดจะกลบเรื่องอื่นที่คนละสาเหตุ
- **line-height 1.7** เพราะภาษาไทยมีวรรณยุกต์ซ้อนบนสระบน ค่าปกติของ Tailwind บรรทัดชนกัน

## โครงสร้าง

```
src/lib/workspace.ts       ชนิดข้อมูล + สัญญา WorkspaceSource (ไม่มีตรรกะ)
src/lib/today.ts           ตรรกะ Today View ทั้งหมด — เทสต์ได้ ไม่พึ่ง React
src/lib/demo-workspace.ts  ข้อมูลตัวอย่าง สร้างจาก planCalendarSlots() ของจริง
src/lib/format.ts          จัดรูปแบบวันเวลา/ตัวเลขสำหรับสายตาคนไทย
src/components/            ชิ้นส่วน UI (เขียนเอง ไม่ได้ใช้ shadcn CLI)
```

**ตรรกะการเรียงลำดับอยู่ที่ `today.ts` ไม่ใช่ใน component** เพราะการตัดสินว่า
"อะไรด่วนกว่าอะไร" คือสิ่งที่ผิดแล้วเสียลูกค้า ต้องมีเทสต์คุม (`today.test.ts`)

## ต่อกับข้อมูลจริง

ตอนนี้ใช้ `demoSource` พอ Prisma repository พร้อม ให้เขียนตัวที่ implement
`WorkspaceSource` แล้วสลับที่จุดเดียว — หน้าจอไม่ต้องแก้

เวลาทุกค่าที่ส่งเข้ามาเป็น epoch ms แบบ UTC (กฎข้อ 4) แล้วแปลงตาม
timezone ของเพจตอนแสดงผลเท่านั้น
